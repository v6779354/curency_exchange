# Миникошелёк путешественника

Telegram-бот на Python 3.10+ и pyTelegramBotAPI. Интерфейс на русском,
данные в SQLite рядом с проектом (`wallet.sqlite3`).

## Запуск

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# Если .env ещё нет: cp .env.example .env
python bot.py
```

В `.env` нужны `TELEGRAM_BOT_TOKEN` (BotFather) и `CURRENCY_API_KEY`
(exchangerate.host). Существующий `.env` не перезаписывается. Запускайте один
процесс бота на токен/базу. Бот работает в личном чате, через long polling.
Для бота с ранее настроенным webhook сначала отключите webhook.

## Использование

1. `/start` → «Создать новое путешествие».
2. Введите страны отправления и назначения: например, Россия и Китай.
   Поддерживаются русские/английские названия, ISO-коды RU/CN и распространённые
   сокращения. Если действующих валют несколько, бот предложит выбрать одну.
3. Бот проверит пару через API и покажет курс **валюта назначения за 1 домашнюю**.
   Примите его или введите и подтвердите ручной курс.
4. Введите начальную сумму **в домашней валюте**. Бот запросит конвертацию этой
   суммы в API и покажет итог перед созданием. Для курса API он уточняется на
   этом шаге; для ручного курса кошелёк использует ручное значение, а результат
   API показывается отдельно для сравнения.
5. Отправьте `100` или `100,50`: это расход в валюте назначения. Списание
   происходит только после «✅ Да». «❌ Нет» отменяет операцию.

Главное inline-меню: создание, выбор путешествия, баланс, история, изменение
курса. Альтернативы: `/newtrip`, `/switch`, `/balance`, `/history`, `/setrate`.
`/start`, `/help`, `/menu`, `/cancel` открывают меню и отменяют текущий ввод.
Список путешествий и история имеют страницы.

## Правила кошелька

- Каждый пользователь видит только свои путешествия. Активное путешествие,
  незавершённый диалог и ожидающие подтверждения расходы переживают перезапуск.
- Курс фиксируется для путешествия. Конвертация расходов — деление на этот курс,
  без нового сетевого запроса: так ручной обменный курс применяется ко всем расходам.
- Остаток хранится в валюте назначения; домашний эквивалент рассчитывается по
  текущему курсу путешествия. Начальные суммы сохраняются в обеих валютах.
- Изменение курса сохраняет местный остаток, переоценивает домашний эквивалент,
  сохраняет исторические суммы расходов и отменяет старые неподтверждённые расчёты.
- Все денежные вычисления — `Decimal`; суммы округляются по точности валюты
  (например, CNY/RUB — два знака, JPY — целые) с `ROUND_HALF_UP`.
- Начальная сумма и расход должны быть положительными. Перерасход не разрешён.
- Подтверждение привязано к исходному путешествию, даже после переключения.
  Списание и запись истории выполняются одной транзакцией; повторное нажатие
  или одновременные подтверждения не приводят к повторному списанию.
- В истории сохраняются время UTC, обе суммы и курс на момент расчёта.

## API

Единственный модуль запросов курсов — `current_api.py`. Единственный адрес:

```text
http://api.exchangerate.host/convert
    ?access_key=<значение CURRENCY_API_KEY>
    &from=RUB&to=CNY&amount=1
```

Имя параметра аутентификации в API — **access_key**, имя переменной в `.env` —
**CURRENCY_API_KEY**. Другие валютные API и endpoints не используются.
Редиректы отключены, чтобы все запросы оставались на заданном HTTP endpoint.
HTTP выбран по условию задачи; этот протокол передаёт ключ без шифрования.

`/convert` не предоставляет справочник стран. Названия и действующие валюты
определяются локально через pycountry/Babel (CLDR), затем выбранная пара
проверяется реальным `/convert`. Актуальность справочника зависит от версии Babel.
Доступность `/convert` зависит от тарифа аккаунта; отказ API (в том числе код 105),
неизвестные валюты, тайм-ауты и некорректные ответы показываются понятным сообщением.
При сбое API путешествие не создаётся с выдуманным курсом.

Документация:
- https://exchangerate.host/documentation
- https://pytba.readthedocs.io/en/latest/sync_version/index.html

## Проверки

```sh
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты не отправляют сообщения в Telegram и не расходуют квоту API. Проверяют
пользовательские сценарии, HTTP-контракт, ошибки, точность, изоляцию пользователей,
конкурентные подтверждения, переключение, ручные курсы и сохранение состояния.
`.env`, локальная база и виртуальное окружение исключены из Git.

## Если бот не отвечает

Проверьте соединение без запуска polling:

```sh
.venv/bin/python bot.py --check
```

Команда выводит имя бота, соответствующего токену. Откройте именно этот аккаунт
в Telegram. Обычный запуск `python bot.py` теперь пишет сообщение о подключении
и показывает ошибки Telegram с удалёнными из логов токенами.
Ошибка 409 означает конфликт другого polling-процесса или webhook: остановите
другие экземпляры. После изменения кода остановите старый процесс через Ctrl+C
и запустите заново.
